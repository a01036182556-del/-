# 건설기계 기초자료 관리대장

여러 건설기계 장비의 등록·검사·보험·운전원·배치현장 정보를 **한 표**로 관리하는 Excel
대장을 만들고 채우는 스킬이다. 장비 작업계획서(1대짜리 법정 서식)와는 목적이 다르다 —
이건 현장/회사가 보유·투입 중인 장비 전체를 한눈에 보는 레지스트리다.

이 스킬의 스크립트 위치는 이 SKILL.md 상단에 표시된 "Base directory for this skill"
경로 아래 `scripts/`다 (예: `<base>/scripts/ledger_lib.py`).

## 언제 새로 만들고, 언제 이어서 채우는가

1. 사용자에게 기존 대장 파일이 없으면(또는 새로 시작하고 싶다고 하면) → **새 대장 생성**.
2. 사용자가 대장을 이미 갖고 있고(이 세션에서 만들었거나 파일을 올려줬거나) 장비 서류를
   추가로 올렸다면 → **기존 대장에 행 추가**. 기존 행은 절대 덮어쓰지 않는다.
3. 장비가 몇 대인지 확실치 않거나 서류만 덜렁 올라온 경우, 대장이 이미 있는지부터
   확인하고 없으면 먼저 빈 대장을 만든 뒤 서류로 채우는 순서로 진행한다.

## 1단계 — 대장 생성 (새 대장일 때)

```bash
python <base>/scripts/create_ledger.py <output_path.xlsx>
```

이 한 줄로 정해진 레이아웃(아래 열 구성, 서식, 예시행 1개, 빈 입력행 25개)의 워크북이
만들어진다. 열 구성이나 서식을 사용자가 다르게 요청하지 않는 한 이 구조를 그대로
쓴다 — 이미 실제 사용자와 함께 검증된 레이아웃이다.

## 2단계 — 장비 서류에서 데이터 추출

업로드된 파일은 보통 다음 중 일부/전부가 섞인 PDF(또는 여러 PDF/이미지)다:

- **건설기계 작업계획서(갑지)** — 이미 채워져 있다면 가장 밀도 높은 단일 출처다. 종류,
  모델명, 제작사, 형식, 용량, 등록번호, 사용위치, 정기검사 유효기간, 사용기간,
  보험 만료기간, 운전자 성명, 면허종류, 취득일, 연락처가 표 하나에 다 들어있다.
- **건설기계등록·검사증** (양면) — 앞면: 소유자 성명/주소, 차대일련번호, 제작연도,
  제원(형식승인번호 등). 뒷면: 검사이력표(정기검사 일자·유효기간·검사기관, 보통
  손글씨로 갱신됨 — 가장 최근 줄이 현재 유효기간이다).
- **자동차보험 가입증명서 / 보험증권** — 보험회사, 계약(증권)번호, 보험기간, 피보험자.
- **건설기계조종사면허증** 또는 **화물운송종사자격증** — 면허/자격 종류, 번호, 취득일.
  건설기계조종사면허 자체는 보통 만료가 없고, 대신 3년 주기 안전교육 유효기간이
  실질적 만료 역할을 한다 (안전교육 이수증에 표시됨) — 이 경우 면허유효기간 칸에는
  안전교육 유효기간을 쓰고 취득일도 함께 적어 어떤 날짜인지 명확히 한다.
- **사업자등록증** — 상호(=소유자/임대업체명), 성명(=대표자), 사업자등록번호.
- 제조사 스펙 카탈로그, 정격하중표, 건강진단표 등은 대장에는 보통 불필요 — 참고만 한다.

**읽는 방법:**
1. 업로드 파일이 PDF면 `pdfinfo`로 실제 페이지 수를 먼저 확인한다 — 업로드 메타데이터의
   페이지 수가 실제와 다를 때가 있다 (이 세션에서 38페이지로 안내됐지만 실제로는
   18페이지였던 사례가 있었다).
2. `Read` 툴을 PDF에 직접 쓰면(20페이지 제한이므로 `pages` 범위를 나눠서) 페이지를
   이미지로 렌더링해 보여준다 — 타이핑된 작업계획서 페이지와 스캔된 증명서 이미지를
   모두 육안으로 읽는 데 이 방법이 OCR/pdfplumber보다 안정적이었다.
3. `pdftotext -layout`으로 페이지별 글자 수를 빠르게 훑으면 어느 페이지가 순수 스캔
   이미지인지(추출 글자 수 0에 가까움 → `Read`로 시각적으로 읽어야 함) 미리 알 수 있다.
4. 같은 값이 여러 서류에 나오면(등록번호, 보험기간 등) 인쇄된 공식 서류(등록증, 보험증권)
   가 손글씨 작업계획서보다 우선한다 — 서로 다르면 더 신뢰도 높은 쪽을 쓰고, 필요하면
   비고나 셀 메모에 두 값을 모두 남긴다.

**필드 매핑 요령:**
- 종류 → 장비명(기종) · 모델명(+톤수/용량) → 규격/모델명 · 차량등록번호 → 등록번호 ·
  차대일련번호/원동기형식 → 차대(형식)번호 · 제작사 · 제작연도(등록증의 "제작년도")
- 사업자등록증 상호 → 소유자(임대업체) · 사업자등록증 성명 → 대표자
- 정기검사 유효기간 → 검사유효기간(검사종류는 특별한 언급 없으면 "정기검사")
- 보험회사/증권번호/보험기간
- 운전원 성명/면허종류/면허번호 · 사용위치·공종·작업내용 → 배치현장 ·
  작업기간 시작일 → 반입일
- 협력업체명, 신호수·작업지휘자 연락처 등 표에 넣기 애매한 부가정보는 비고에 모아 적는다.

## 3단계 — 대장에 행 추가

새 대장이든 기존 대장이든, `ledger_lib.append_row()`로 한 대씩 추가한다. 연번은
자동으로 매겨지고, 미리 만들어둔 빈 행 25개를 다 쓰면 서식을 유지한 채 자동으로
행이 늘어난다 — 몇 번째 빈 행인지 직접 셀 필요 없다.

```python
import sys
sys.path.insert(0, "<base>/scripts")
from ledger_lib import append_row

row = append_row(
    "관리대장.xlsx",
    values={
        2: "이동식크레인(라프터크레인)",
        3: "SL-600Ⅱ(KR-50H-L2) / 51톤",
        4: "대전007가8717",
        6: "KATO(가토)",
        7: 2006,
        # ... 확인된 값만 넣는다. 모르는 열은 아예 빼도 되고, "-"를 넣어도 된다.
    },
    comments={
        12: "등록·검사증 뒷면 손글씨 기재분으로 판독이 어려워 추정 입력했습니다. 원본 대조 필요.",
    },
)
print(row)
```

열 번호는 위 표를 보거나 `python <base>/scripts/ledger_lib.py`를 실행하면 출력된다.

장비 서류가 여러 건 한 번에 올라왔으면(예: 이번 요청에 PDF 2~3개) 장비별로
`append_row`를 반복 호출해 각각 한 행씩 만든다 — 한 행에 여러 장비를 욱여넣지 않는다.

저장 후에는 결과 파일을 사용자 출력 위치로 복사하고 `SendUserFile`로 보낸다.

## 판독 불가한 데이터를 절대 지어내지 않는다

손글씨, 초서체, 마스킹/가림, 여러 서류 간 이름 표기 불일치처럼 확신할 수 없는 값을
만나면:

- 그럴듯해 보이는 값을 조용히 지어내지 말고, 셀에는 상태를 알 수 있는 짧은 문구를
  쓴다. 예: `"판독 어려움(원본 확인 필요)"`, 또는 일부만 읽혔다면
  `"○○04○8206 (등록번호 필체 판독 어려움)"`처럼 읽은 부분 + 괄호 설명.
- 해당 셀에 `comments={...}`로 무엇이 왜 불확실한지 구체적으로 남긴다 (예: 정정선으로
  가려진 글자, 서류 간 성명 표기가 달랐던 부분).
- 어느 서류에도 아예 없는 정보(예: 소유자 휴대전화가 업로드된 서류 어디에도 없음)는
  추측하지 말고 `"-"`를 넣고, 보통 어떤 서류에 그 정보가 있는지 코멘트로 남긴다.
- 채팅 답변 마지막에 어떤 항목이 불확실/판독 어려움으로 표시됐는지 명시적으로 정리해
  주고, 더 선명한 스캔본이 있으면 재업로드를 제안한다.

지어낸 값 하나가 실제 안전서류 대장에 잘못 들어가면 검사·보험 만료를 놓치는 등 현장
사고로 이어질 수 있다 — 빈칸이나 "판독 어려움"이 틀린 값보다 항상 낫다.
